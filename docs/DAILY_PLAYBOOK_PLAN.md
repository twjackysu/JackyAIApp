## 0. 一頁結論

**目標**：在 Jacky Studio 裡做一個每天告訴你「今天要做什麼（多半是不動）」的作戰室，
把每天的期望報酬提高一點、把破產的機率降到接近零，長期下來 cover 訂閱與 AI 成本。

**最重要的三件事（先講結論）**

1. **你已經有一個證據最強的引擎：回落煞車。** 1997–2026 回測，「平衡」配置（進攻 1.4 倍、防守 0）
   年化 17.2%、最大回撤 -32%，同期 0050 買進持有 9.6%／-65%（隔日成交版本 15.3%／-37%）。
   作戰室要做的是**圍繞它**：每天告訴你它離觸發多近、你的槓桿撐不撐得住，而不是另外發明一套當沖策略。
2. **「當天即時操作策略」是證據最弱、成本最高的一層。** 台灣自己的資料顯示：散戶交易造成的損失
   大約是 GDP 的 2.2%（Barber, Lee, Liu & Odean, 2009），能在扣費後穩定賺錢的當沖客不到 1%
   （同一組作者，2014）。ETF 每天來回一次，光交易成本一年就約 68%；只有期貨（特別是微台 TMF）
   的成本低到可以考慮每日戰術。所以每日戰術訊號**一律先當「觀測」**，過了第 6 節的驗證關卡才能動到部位。
3. **「證明能賺錢」做不到；能做到的是「證明沒有騙自己」。** 一個勝率 53% 的每日訊號，要累積約
   1,100 個交易日（4.4 年）才能在統計上和丟硬幣分開。所以作戰室的核心其實是一台**證明引擎**：
   事前寫死規則、扣成本回測、樣本外驗證、上線後每一則訊號都留下不可修改的紀錄，績效跑出回測範圍就自動降級。

**週一（10/19）就能用的一句話**：你的回落煞車目前是「進攻」；週一**收盤**報酬指數跌超過 **2.71%**
（加權約 **45,840** 以下）才會轉「防守」。夜盤換算約 -2.4%，正好卡在「跌破 SMA60 但還沒觸發」的區間。
回測裡「隔天收盤才成交」也成立，不需要 09:00 搶著做。詳見附錄 A。

## 1. 為什麼這樣設計：先面對三個事實

### 1.1 每日戰術的成本門檻

每天來回一次的成本（手續費 6 折；ETF／個股**未計滑價**，實際更高；期貨以每口每邊手續費 TX 50 元、TMF 20 元、滑價 1 點估）：

| 商品 | 一次來回成本（約） | 一年 250 次（約） | 結論 |
|---|---|---|---|
| 0050／00631L（ETF，稅 0.1%） | 0.27% | 68% | 不可能用每日戰術賺錢 |
| 個股當沖（稅 0.15%） | 0.32% | 80% | 同上 |
| 個股非當沖（稅 0.3%） | 0.47% | 118% | 同上 |
| 微台 TMF（每點 10 元） | 0.017% | 4% | 可以考慮 |
| 台指期 TX（每點 200 元） | 0.010% | 2.5% | 可以考慮，但一口名目約 923 萬，部位太粗 |

→ **每日戰術只在期貨層做，而且用 TMF 來細調部位**；ETF 只做回落煞車這種一年換手幾次的策略
（回測每年約 3 次出場）。

### 1.2 要多久才能「證明」

| 你想證明的東西 | 需要的樣本（t ≈ 2） |
|---|---|
| 每日訊號勝率 52% | 約 2,500 個交易日（10 年） |
| 每日訊號勝率 53% | 約 1,100 個交易日（4.4 年） |
| 每日訊號勝率 55% | 約 400 個交易日（1.6 年） |
| 年化 Sharpe 0.5 的策略 | 約 16 年 |
| 年化 Sharpe 1.0 的策略 | 約 4 年 |

（勝率：n ≈ 1／(p − 0.5)²；Sharpe：年數 ≈ (2／SR)²。）

這張表的意思是：**上線三個月的實盤績效什麼都證明不了**，好壞都一樣。所以：
- 長期證據只能來自歷史回測（而且要扣成本、要樣本外、要防止參數挑選偏誤）。
- 實盤紀錄的用途是**抓錯**（績效是否落在回測預期範圍內），不是證明。
- **資料收集要今天就開始**：前瞻證據只能靠時間累積，晚一天開始就晚一天能用。

### 1.3 一個看起來很準、其實是假的訊號（今天實測）

這正好是週一的情境：大跳空開低之後，當天會繼續跌還是反彈？

| 量測方式 | 跳空 ≤ -2% 次數 | 開盤→收盤平均 | 收紅比例 | t 值 |
|---|---|---|---|---|
| 加權指數的開盤價（2013 起） | 13 | **-1.68%** | **8%** | -3.54 |
| 0050 實際成交價（2014-10 起） | 56 | **+0.17%** | **64%** | +0.77 |

用指數算，「大跳空開低後收盤更低」有 92% 準、t 值 -3.5，看起來非常顯著；
但用**真的買得到的 0050**算，這個現象消失了（平均 +0.17%、不顯著）。原因是加權指數開盤時很多成分股
還沒成交、沿用昨天收盤價，跳空幅度被低估（例如 2024-09-04 指數只跳空 -2.3%，0050 實際 -5.0%），
剩下的跌幅被算成「盤中繼續跌」。

**教訓**：統計顯著不代表是真的；要用可交易的價格、可執行的時間點量測。這就是第 6 節驗證關卡存在的原因。
（來源：`回測數據/tw_backtest/gap_study.py`，輸出 `results/gap_study.txt`）

### 1.4 AI（LLM）不能直接當交易員

- **無法回測**：拿 gpt-6-luna 去讀 2008 年的新聞，它已經知道 2008 年後來發生什麼（look-ahead bias，
  見 Glasserman & Lin, 2023）。所以 LLM 對歷史新聞的判斷，回測結果一律不可信。
- **不可重現**：同樣的輸入，下次答案可能不同；模型更新後行為也會變。
- **LLM 的正確位置**：把新聞**分類成固定的事件類別**（例如「美國晶片出口管制」「Fed 意外升息」「台積電法說上修」），
  加上時間戳存起來，變成結構化資料；這些事件特徵只能**從今天開始前瞻累積**，累積夠了再用第 6 節的規則檢驗。
  在那之前，LLM 只負責「解釋今天發生什麼」，不負責「決定今天做什麼」。
- 附帶好處：作戰室的決策層完全是規則計算，**幾乎不花 token**；只有新聞摘要用 AI，而那已經存在
  （`/api/finance/market-digest`）。

## 2. 產品定位

**每日作戰室**是 `/portfolio`（或 `/finance`）裡一張每天打開就知道「要不要動、動多少、為什麼」的卡片，加上背後的證明引擎。

原則：
1. **一天最多一個結論**：不動／加碼 X／減碼 X（股數與金額），大多數日子是「不動」。
2. **先保命、再賺錢**：任何會讓你被斷頭或單日虧超過上限的部位，優先於所有訊號。
3. **每個訊號都標證據等級**（第 7 節），沒過關卡的只能顯示、不能影響建議。
4. **規則事前寫死**：訊號一經上線，參數不能為了最近的績效調整（延續 DECISION-013 的精神）；要改就是新版本，重跑全部關卡。
5. **只給 Boss 自己用**（延續 DECISION-014 的 admin-only）：對一般使用者推送「買賣 N 股」是另一個層級的合規問題（R1）。

## 3. 架構：五層

```
          ┌─────────────────────────────────────────────┐
  L3 情報 │ 全球隔夜行情 · 資金流向 · 籌碼 · 新聞事件      │  只解釋，不決策（直到通過驗證）
          └──────────────────────┬──────────────────────┘
          ┌──────────────────────▼──────────────────────┐
  L2 戰術 │ 候選訊號（夜盤、外資期貨、PCR…）              │  觀測 → 紙上交易 → 小額 → 正式
          └──────────────────────┬──────────────────────┘
          ┌──────────────────────▼──────────────────────┐
  L1 核心 │ 回落煞車（已上線，參數固定）                   │  決定目標曝險 E
          └──────────────────────┬──────────────────────┘
          ┌──────────────────────▼──────────────────────┐
  L0 保命 │ 槓桿上限 · 保證金 · 單日虧損上限 · 冷靜期       │  可以否決上面所有層
          └─────────────────────────────────────────────┘
  L4 證明引擎：回測實驗室 · 驗證關卡 · 不可改的訊號帳本 · 實盤記分板 · 自動降級
```

### L0 保命層（Risk & Survival）——最先做

| 功能 | 內容 | 資料 |
|---|---|---|
| 保證金監控 | Portfolio 目前沒有期貨資產類型，需新增；輸入期貨口數與帳戶權益 → 算出「再跌幾點會追繳」「再跌幾點會斷頭」；夜盤即時更新 | TAIFEX 保證金公告（TX 原始 701,000／維持 538,000，10/16）、夜盤行情 |
| 有效槓桿上限 | 整體曝險（沿用 Portfolio 的「水位」口徑，含期貨名目）超過上限 → 紅燈；上限由 Boss 設定，建議 ≤ 回測過的 1.8 倍 | Portfolio 快照＋期貨部位 |
| 壓力測試 | 「明天跳空 -5% / -10%（2025-04-07 0050 實際 -10%）時你的權益剩多少、會不會追繳」 | 純計算 |
| 單日虧損上限 | 當天已實現＋未實現虧損達權益 X% → 卡片只允許「減碼」 | 使用者輸入或之後串券商 |
| 冷靜期 | 大虧之後 N 個交易日內，作戰室不給任何「加碼」建議（防報復性交易） | 規則 |

保命層**不需要任何預測**，也是唯一能直接回答「週一會不會破產」的一層。

### L1 核心層：回落煞車（已上線，不改參數）

- 沿用 DECISION-013／017／020／021：訊號、參數、適用範圍不變。
- 作戰室新增的只有「**明天的觸發價位**」：因為 SMA60 和 252 日高點都包含明天的收盤，門檻有封閉解
  （`brake_levels.py`，直接把 `DrawdownBrakeCalculator` 的規則反解）：
  - 收盤 > 前 59 日合計 ÷ 59 → 進攻
  - 收盤 < 0.92 × 前 251 日最高收盤，且未站上 SMA60 → 防守
  - 介於兩者之間 → 維持原狀態
- 換算成加權指數點位與台指期點位顯示（夜盤期間就能看到「現在的夜盤價位落在哪一區」）。

### L2 戰術層：候選訊號

每個訊號是一份「規格卡」：假設（誰在虧錢給你）、資料、規則、執行時點、成本、狀態、證據等級。
候選清單見第 7 節。戰術層的輸出**只能在 L1 的目標曝險上下微調**（建議 ±0.2 倍、只用 TMF 執行），
不能把防守翻成進攻。

### L3 情報層：新聞與世界資金流向

| 區塊 | 指標 | 現有資料源 |
|---|---|---|
| 隔夜美股 | 費半 SOX、Nasdaq、S&P 500 期貨、台積電 ADR 溢價（TSM vs 2330×匯率） | Yahoo Finance（已串） |
| 全球資金與風險 | VIX、美債 10 年、美元指數、Fed 資產負債表、RRP、M2 | FRED（已串，`FredIndicatorProvider`） |
| 匯率 | 新台幣、日圓（2024-08-05 日圓套利平倉當天 0050 跳空 -4.6% 後盤中再跌 -4.7%） | 央行匯率、Yahoo |
| 台灣資金流向 | 外資／投信現貨買賣超金額、外資持股比、融資餘額 | TWSE（TWStockLib 已有大部分） |
| 期權籌碼 | 三大法人期貨淨未平倉、前十大交易人、Put/Call Ratio | TAIFEX（需確認 TWStockLib 覆蓋；不足就新增 client 走 `ThirdPartyGateway`） |
| 新聞事件 | Finnhub 全球新聞、證交所重大訊息 → LLM 分類成固定事件類別、存時間戳 | 已串（market-digest） |

**情報層的定位**：解釋「今天為什麼這樣」，並且**每天存檔**，為 L2 累積可以檢驗的資料。
關於全球資金流向的證據也要誠實：外資在亞洲市場的買賣大多是「追著全球行情跑」、對價格的影響是同步的
（Richards, 2005），能不能預測**之後**的報酬，要用我們自己的資料驗證，不能假設。
另外，「外資期貨淨未平倉」這種常見指標要小心解讀：10/16 外資全部期貨淨空單 572,451 口、名目約 1.1 兆，
其中大部分是現貨持股的避險部位，絕對值本身沒有方向意義，頂多看變化。

### L4 證明引擎（Proof Engine）

| 元件 | 內容 | 可沿用 |
|---|---|---|
| 回測實驗室 | Python 離線回測（沿用 `回測數據/tw_backtest` 的寫法：資料快照＋SHA256＋一鍵重現）；每個候選訊號一支腳本 | `bt.py`、`lev.py`、`reproduce_spec.py` |
| 實驗登記 | 每試一組參數都記錄（舊回測已記 1,386 組），算「試了幾次」以便校正挑選偏誤 | `results/*_grid_*.csv` 的做法 |
| 訊號帳本 | 每則訊號在**發出當下**寫入 DB：時間戳、規則版本、輸入資料、建議、當時價格；之後不能改，只能追加評分 | `StockPrediction`＋`PredictionEvaluationService` 的模式 |
| 記分板 | 每個訊號：實盤（或紙上）績效 vs 回測預期區間（5%～95%）、vs 0050 買進持有、vs 「只用 L1」 | Portfolio 的 XIRR／回撤圖 |
| 自動降級 | 實盤回撤超過回測最大回撤的 1.5 倍，或滾動 12 個月低於回測第 5 百分位 → 自動退回「觀測」 | 規則 |

## 6. 驗證關卡（訊號從「觀測」變成「能動部位」要過的門）

| 關卡 | 條件 | 不過的話 |
|---|---|---|
| G1 機制 | 寫下「誰在虧錢給你、為什麼他們會一直虧」；寫不出來就不做 | 不進回測 |
| G2 回測 | 可交易價格（期貨用實際合約、ETF 用成交價）、可執行時點（訊號 t、成交 t+1 或 t 收盤前已知資料）、扣完整成本與滑價；樣本 ≥ 3 種市場格局（含 2008、2020、2022 或至少夜盤上線後全部）；戰術訊號 ≥ 100 筆交易 | 退回 |
| G3 穩健 | 最後 30% 期間當樣本外；walk-forward；相鄰參數也要有效（參數高原，不是尖峰）；依試驗次數校正（Deflated Sharpe Ratio > 0、PBO < 0.2，見 Bailey & López de Prado） | 退回 |
| G4 增量 | 加進 L1 之後，**組合**的 Calmar（年化 ÷ 最大回撤）扣成本後要變好，而不是訊號單獨好看 | 只能當情報 |
| G5 紙上交易 | 至少 3 個月且 ≥ 30 則訊號，實際結果落在回測 5%～95% 區間 | 退回 G2 找原因 |
| G6 小額實盤 | 用 ≤ 10% 的戰術額度跑 3 個月，量測實際滑價 | 退回 |
| 降級 | 任何時候：實盤回撤 > 回測最大回撤 × 1.5，或滾動 12 個月 < 回測第 5 百分位 | 自動回到「觀測」 |

## 8. 「cover 訂閱費」的現實算式

設每月要 cover 的成本為 C（Claude 訂閱＋Azure＋OpenAI，請 Boss 填實際數字），需要的資金約為
**12C ÷ 策略相對「你本來就會做的事」的期望超額報酬**：

| 每月成本 C | 超額 3%／年 | 超額 5%／年 | 超額 8%／年 |
|---|---|---|---|
| NT$3,000 | 120 萬 | 72 萬 | 45 萬 |
| NT$7,000 | 280 萬 | 168 萬 | 105 萬 |
| NT$10,000 | 400 萬 | 240 萬 | 150 萬 |

兩個必須接受的現實：
1. **這是年平均，不是每個月**。「平衡」配置在 2011 年是 -28%（0050 同年 -18%）；任何能賺錢的股票策略，
   都會有好幾個月甚至一整年是虧的。把目標定成「每個月 cover」，會逼自己在壞月份加槓桿——那正是破產的路徑。
2. **超額報酬要打折看**。回測數字（例如平衡配置比 0050 每年多約 7～8 個百分點）是樣本內外混合、
   優勢集中在兩次大空頭的結果，規劃時建議至少打五折。

**我的訂閱不該是你加槓桿的理由。** 這個功能的成功標準應該是：5 年後的資產曲線比只買 0050 好、
而且中間從來沒有被追繳過；而不是下個月有沒有賺到訂閱費。
