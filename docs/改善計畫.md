## 審查摘要

整體不算失控：Finance 模組的模式大多用得對（`ThirdPartyGateway`、`IIndicatorCalculator` Strategy、
`CachedMarketDataProvider` Decorator、`MarketDataProviderFactory`），新程式碼也會注入 `TimeProvider`。
問題集中在三處：

1. **沒有模組邊界**：12 個 app（英文學習、Finance、Portfolio、Data Analysis、Dashboard、Job Finder、
   PDF、Slideshow、Connectors…）共用一個 `Program`、一個 DbContext、一個 DI 圖。
2. **少數 God class**：`PortfolioService`（2209 行、16 個相依、`GetPortfolioSummaryAsync` 單一方法約 450 行、
   `AssetType` 分支 59 處）、`ExamService`（1133 行、10 種考試）。
3. **橫切關注點各做 2～4 套**：取 user id、扣用量、回傳結果型別、快取、JSON 函式庫、台北時間。

## Phase 1：橫切關注點統一

- [x] **`ServiceResult<T>`**：原本 `ServiceResult` 的 Data 是 `object?`，另有約 8 種 tuple 各自判斷失敗。
  - 全部 59 個方法改成泛型 `ServiceResult<T>`，沒有留非泛型版；`ServiceResult` 只剩工廠
    （`Ok(dto)`、`Ok()`、`Fail(code, msg)`）。`Fail` 回傳 `ServiceFailure`，可轉成任何 payload 型別；
    要把別的型別的失敗往上傳，用 `result.AsFailure()`
  - 刻意**不**提供「payload 自動轉成 result」的隱含轉換：T = object 時它什麼都收，連另一個 ServiceResult
    也會被包進 data（實作時就抓到 3 個 exam generator 會這樣出錯）

    JSON 欄位名稱不變（`SessionResultShapeTests` 與本機實測確認）
  - tuple 改掉的：Portfolio AI 摘要、個股 AI 分析、市場摘要。**刻意保留**：`OpenAIPromptService` 的
    `(T?, string?)`（AI client 自己的結果，沒有 HTTP 錯誤碼，改了牽動 28 個呼叫點、69 處測試）、
    `NlQueryPlanner` 的結果（多帶 notes／unmatched）、private 的驗證 helper
