## 審查摘要

整體不算失控：Finance 模組的模式大多用得對（`ThirdPartyGateway`、`IIndicatorCalculator` Strategy、
`CachedMarketDataProvider` Decorator、`MarketDataProviderFactory`），新程式碼也會注入 `TimeProvider`。
問題集中在三處：

1. **沒有模組邊界**：12 個 app（英文學習、Finance、Portfolio、Data Analysis、Dashboard、Job Finder、
   PDF、Slideshow、Connectors…）共用一個 `Program`、一個 DbContext、一個 DI 圖。
2. **少數 God class**：`PortfolioService`（2209 行、16 個相依、`GetPortfolioSummaryAsync` 單一方法約 450 行、
   `AssetType` 分支 59 處）、`ExamService`（1133 行、10 種考試）。
3. **橫切關注點各做 2～4 套**：取 user id、扣用量、回傳結果型別、快取、JSON 函式庫、台北時間。

## Phase 1：橫切關注點統一

- [ ] **`ServiceResult<T>`**：現有 `ServiceResult` 的 Data 是 `object?`，另有約 8 種 tuple
  （`(T?, string?)`、`(T?, string?, ErrorCodes?)`…）各自判斷失敗。改成泛型，加 `ToActionResult<T>` overload；
  可漸進，非泛型版先保留
- [ ] **用量扣點只留一種機制**：現在 `[UsageLimit]` 10 處、controller 手寫 4 處、service 手寫 8 處。
  - cost 和 feature 字串合成一個 `UsageFeature` value object，避免配錯
  - 未登入時 attribute 回 `Forbidden`，其他地方回 `Unauthorized` → 統一
  - 失敗退點目前只有 chatbot 做 → 決定一個全站規則（需決策）
- [ ] **`ICurrentUser`**：`IUserService.GetUserId()` 和 `ApiControllerBase.CurrentUserId` 合一；
  已掛 `[Authorize]` 的 action 不再寫 `userId == null` 樣板（目前 50 處）
- [ ] **`ITaipeiClock` + `ITradingCalendar`**：`UtcNow.AddHours(8)` 散在 7 個檔；休市日曆改成存 DB／背景預熱，
  不在請求路徑上即時抓。完成後 `PortfolioService.PreviousTradingDay` 改用它
- [ ] **快取**：手寫 `TryGetValue/Set` 53 處改用 `GetOrCreateSingleFlightAsync`；移除 `IExtendedMemoryCache`，只留 `IMemoryCache`
- [ ] **移除 Newtonsoft.Json**（10 個檔），全站只用 System.Text.Json
- [ ] **`ExceptionMiddleware`**：不再把 request body／form 欄位寫進 log（可能含個資）；
  `EnableBuffering` 不要對每個請求都開
- [ ] **`StockCodeResolver`**：兩段近乎相同的 inline prompt 移到 `Prompt/Finance/`，改走 `OpenAIPromptService`
- [ ] **`JiraConfig`**：有 DbSet 和資料表但沒有任何讀寫。刪除需要一個 drop table 的 migration，
  部署時會在正式 DB 執行 → 先確認正式資料表是空的（需決策）
- [ ] `DTO/NewModels.cs`（模型名稱常數）移到 `Common/`；`Data/Models/*.cs` 的 namespace 與資料夾對齊
